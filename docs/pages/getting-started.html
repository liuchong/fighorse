Get started / CLI first

五分钟，
获得可靠上下文。

先走 CLI 路径：构建、安装、认证、验证、生成设计包。只有当 AI 客户端需要直接调用时，再打开共享 MCP 服务。

01 / Build + install

一个 Rust 二进制，
清楚完成安装。

从源码构建需要 Rust 1.86 或更高版本。默认安装复制二进制、生成本地配置和 AI 指导文件，不启动长期服务。

step 01 / install
$ git clone https://github.com/liuchong/fighorse.git
$ cd fighorse
$ cargo build --release
$ ./target/release/fighorse install --default --apply \
  --source ./target/release/fighorse

已下载二进制？

直接运行 ./fighorse install --default --apply。需要自定义位置时使用 ./fighorse install --path ~/.local/bin --apply。

02 / Authenticate

令牌留在本地。
绝不进仓库。

创建具有所需读取权限的 Figma 个人访问令牌。可以保存到本地 fighorse 配置，也可以只给单次命令使用。

PERSIST / LOCAL

本地登录

fighorse auth login --token <FIGMA_TOKEN>

适合日常 CLI 和本地服务使用。配置文件属于个人，不应提交。

ONE SHOT

单次环境变量

FIGMA_TOKEN=<token> fighorse quickstart

适合临时检查或由现有秘密管理方式注入令牌。

03 / First signal

验证环境，
再读取设计。

quickstart 检查运行与认证状态。随后复制具体 frame、component 或 group 的链接，不要从整个页面开始。

检查就绪

运行 fighorse quickstart；脚本或 AI 可以使用 --format json 获取机器可读结果。

复制节点链接

在 Figma 中选中真实实现范围，再复制选区链接。团队资源盘点则使用 team 或 project 浏览链接。

确认目标参数

明确目标平台和资产格式。这两个选择会进入设计包诊断与导出计划。

生成第一份包

把上下文写到项目的 ./.fighorse/exports/package.json，供人和 AI 共同检查。

step 03 / first package
$ fighorse quickstart
$ fighorse design package \
  "https://www.figma.com/design/<fileKey>/<name>?node-id=<node-id>" \
  --platform web-react \
  --asset-format svg \
  --output ./.fighorse/exports/package.json
04 / Optional MCP service

一份能力，
连接多个 AI。

需要 AI 工具直接调用时，安装一个本地共享 HTTP 服务。安装器会在服务真实就绪后，才写入客户端配置。

step 04 / shared service
$ fighorse install --default --mode service \
  --clients cursor,codex,kimi,claude --apply
$ fighorse install verify
CURSOR

原生 URL

客户端配置直接指向本地 /mcp 端点。

CODEX

TOML 配置

安装器生成 [mcp_servers.fighorse] 配置。

KIMI

HTTP 传输

使用明确的 HTTP transport 与同一本地 URL。

CLAUDE

独立安装

也可运行 fighorse install client --client claude --apply。

05 / Checklist

看到这些信号，
再进入实现。

不要把“命令返回了 JSON”误当作上下文已经完整。设计包里的范围、截图和诊断状态才是实现门槛。

READY

可以继续

diagnostics.status=ready；目标节点具体；平台与资产格式明确；截图可用；导出计划可执行。

STOP + NARROW

需要缩小

scope.status=needs_narrowing；目标是 SECTION、CANVAS、DOCUMENT 或 SELECTION。选择 implementable=true 的候选后重试。

06 / FAQ

少走弯路。

这里回答第一次安装和接入最容易混淆的边界。

默认安装会启动后台 MCP 服务吗？

不会。install --default --apply 默认仅完成 CLI 设置，不启动长期服务也不绑定端口。只有明确加入 --mode service 或执行 install service 才会安装服务。

Figma 令牌会被上传吗？

令牌用于向 Figma API 发起你授权的请求。可以保存在个人本地配置，也可以只在单次命令中提供。令牌、配置和私有设计数据都不应提交到 Git。

为什么推荐复制具体 frame 链接？

具体节点让实现范围和诊断更准确。整个 page 或 canvas 往往包含多个屏幕，设计包会要求从可实现候选中进一步缩小。

本地资产导出被拒绝怎么办？

MCP 导出需要显式设置 FIGHORSE_MCP_LOCAL_WRITE=allow，路径必须位于 ./.fighorse/exports、./assets/fighorse 或 ~/.fighorse/exports。

fighorse 会直接生成 React 或 Flutter 代码吗？

不会。它提供准确的设计事实、视觉参考和资产，由 AI 根据目标仓库现有技术与组件结构生成项目原生代码。
