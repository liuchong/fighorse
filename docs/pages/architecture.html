白盒内核。
开放接口。

fighorse 把 API 访问、数据转换、上下文生成和客户端适配分开。人类可以检查每一步，AI 可以调用同一套能力，安全授权不会在层级之间偷偷扩散。

01 / Four layers

从原始事实，
到可行动上下文。

主要差异不只是包装 REST 接口，而是在转换层和上下文层把庞大、嘈杂的数据重塑成 AI 能安全使用的信号。

L1 / SOURCE

Figma API 与资产

公开 REST 操作、files、nodes、images、components、styles、variables、webhooks 与下载。

L2 / TRANSFORM

转换与诊断

compact、filter、diff、token 提取、覆盖报告、经验匹配与预算控制。

L3 / CONTEXT

实现级上下文

设计包、视觉审计、项目 playbook、资源目录、schema 和资产 manifest。

L4 / ADAPTER

CLI 与 MCP

终端命令、共享 HTTP 服务、标准 stdio、资源、prompt、安装器和客户端 skill。

02 / One behavior, two surfaces

CLI 是内核。
MCP 是适配器。

终端和 AI 工具不各自维护一套产品逻辑。它们共享 URL 解析、设计包、资源目录、资产导出和诊断行为。

CLI / WHITE BOX

可脚本、可调试

开发者、CI 和非 MCP agent 可以直接运行二进制文件。数据命令保持机器可读输出，诊断写入标准错误。

MCP / SHARED ACCESS

AI 直接调用

Cursor、Codex、Kimi、Claude、opencode 等客户端复用本机 http://127.0.0.1:9449/mcp，避免重复常驻进程。

一次性命令仍然是一次性进程。

普通 CLI 工作不会启动 MCP 服务、绑定端口或占用服务单例锁。只有显式选择 service 模式，才安装和启动长期运行的本地 HTTP 服务。

03 / Transport

标准会话。
单一端点。

共享服务使用 Rust rmcp 2.2 的 Streamable HTTP。每个客户端拥有独立有状态会话，同时保持一个可管理的本地服务。

SESSION

独立会话

重复初始化不会共享错误状态；不同 AI 客户端保持自己的协议会话。

BOUNDARY

请求校验

在分发前检查 Host 与 Origin，并按标准协商 JSON 或事件流响应。

LIFECYCLE

干净退出

SIGINT、SIGTERM 和标准输入关闭都有明确生命周期，不留下孤儿服务。

transport / canonical
# 推荐：共享 Streamable HTTP 服务
$ fighorse mcp serve --transport http --port 9449

# 仅作显式兼容：标准 stdio
$ fighorse mcp serve --transport stdio
04 / Safety domains

核心安全域，
逐层显式授权。

读取设计、修改 Figma、写本地文件和外发模板代码不是同一件事。它们构成四类核心安全域；Canvas Bridge 在此基础上还有更细的路径级门禁。

DOMAIN / READ

Figma 读取

使用个人访问令牌读取当前用户有权访问的公开 REST 数据，是正常工作模式。

DOMAIN / WRITE

Figma 写入

只有设置 FIGHORSE_MCP_MODE=write 才暴露已实现的写工具。

DOMAIN / FILE

本地导出

MCP 下还需要 FIGHORSE_MCP_LOCAL_WRITE=allow，并限制在三个批准根目录。

DOMAIN / CODE

模板外发

Code Connect 预览或发布需单独设置 FIGHORSE_MCP_CODE_CONNECT=allow。

Canvas 写入还有额外门禁。

本地画布修改必须设置 FIGHORSE_CANVAS_MODE=write；从 MCP 发起时还需要 FIGHORSE_MCP_MODE=write 和逐次 yes=true 确认。执行 Plugin API 脚本必须再设置 FIGHORSE_CANVAS_SCRIPT=allow。多插件会话必须指定 session_id；事务结果为 unknown 时只能先检查或验证，不得自动重试同一计划。

05 / Transactional install

先验证服务，
再触碰客户端。

服务安装不会先写一堆客户端配置再祈祷服务能启动。它按确定顺序执行，记录托管文件，并支持安全回滚。

预检与备份

确认来源、目标和冲突，保存需要恢复的旧内容。

二进制与服务

先落二进制和服务定义，再启动本地服务。

真实就绪

等待 /health，并完成真实 initialize 与 tools/list 握手。

客户端与技能

只有服务可用后，才写 Cursor、Codex、Kimi、Claude 等客户端配置和指导文件。

清单与回滚

manifest 记录哈希、备份和顺序；回滚只恢复仍未被用户修改的托管文件与先前服务状态。

06 / Ecosystem position

专注上下文，
不冒充整个 Figma。

fighorse 与官方 Figma Remote MCP 可以共存。两者边界清楚，才能避免把未公开能力包装成并不存在的“兼容”。

领域fighorse官方 Figma Remote MCP
数据管道白盒 CLI、精简上下文、资产 manifest、视觉审计、本地经验。深度绑定 Figma 产品表面的托管体验。
代码生成不生成目标代码；由 AI 按目标仓库原生实现。可提供产品内 Code to Canvas 等工作流。
Code Connect现代模板兼容层，支持明确的生成、解析、预览和发布。适合自动映射发现等产品内能力。
画布写入通过本地 Figma 开发插件桥，权限逐层开启。官方托管能力与席位规则。
