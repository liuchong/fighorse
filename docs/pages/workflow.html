Workflow / evidence in motion

发现。理解。
实现。验证。

“设计到代码”不是一次生成动作，而是一个证据不断收敛的过程。fighorse 让 AI 在每个关键节点都知道自己掌握了什么、还缺什么。

01 / The golden path

六步主链，
没有魔法跳步。

这条路径同时适用于命令行和 MCP。CLI 便于人类检查，MCP 便于 AI 调用；两者落到同一套产品行为。

自发现

AI 先调用 discover_fighorse，读取当前能力、安全默认值和推荐流程；再用 doctor 检查认证和运行状态。

解析入口

具体设计链接直接解析文件 key 与节点 id。团队或项目浏览链接先进入资源目录，浏览器根链接不会被冒充团队。

缩小范围

选择明确的 frame、component 或 group。若范围诊断返回 needs_narrowing，只从可实现候选中继续选择。

生成上下文

先明确 web、Android、iOS、Flutter 等目标平台，再选择 svg、png、pdf 等资产格式，然后获取设计包和相关历史经验。

实现与导出

按 manifest 定位导出资产；在目标仓库里遵循现有组件、布局和测试结构完成原生实现。

验证与学习

运行应用、捕获截图、执行视觉审计，修正已理解的差异；最后只记录可复用且不包含秘密的经验。

02 / Route the link

不同链接，
走不同的路。

URL 解析不是语法糖，而是防止范围和权限错误的第一道产品边界。

TEAM / PROJECT

资源盘点

进入只读资源目录，列出可访问项目、文件、分支和设计库，然后再选具体文件。

DESIGN / NODE

实现上下文

解析文件 key 和节点 id，检查范围后直接生成设计包。

BROWSER ROOT

停止猜测

公共 REST 无法从浏览器根反查团队时，明确请求团队、项目或具体设计 URL。

03 / AI contract

先问关键问题。
别用默认值装懂。

平台和资产格式会改变布局组件、字体处理、资源格式和实现策略。缺失时必须询问，而不是默认选择 PNG 或某个框架。

REQUIRED / 01

目标平台

Web、Android Compose、iOS SwiftUI/UIKit、React Native、Flutter 或桌面。平台决定实现原语与验证环境。

web-reactandroid-composeios-swiftuiflutter
REQUIRED / 02

资产格式

PNG 是安全渲染回退，不是默认产品选择。应结合平台、缩放需求和设计内容选择 SVG、PDF、WebP 或其他格式。

svgpngpdfwebp

范围同样需要明确。

SECTION、CANVAS、DOCUMENT 或 SELECTION 往往包含多个屏幕。fighorse 会返回候选，而不会静默替你选一个子节点。准确范围来自用户意图与设计事实的共同确认。

04 / Visual loop

第一版代码，
只是第一次测量。

浏览器、移动渲染器、字体、抗锯齿和系统界面都会让真实应用偏离 Figma。高保真实现必须经过反馈循环。

INPUT / 01

Figma 参考

节点结构、准确尺寸、设计令牌、渲染截图与导出资产。

BUILD / 02

项目实现

使用目标仓库自身组件和布局方式实现，不复制错误的框架假设。

MEASURE / 03

真实截图

在目标视口或设备上捕获运行结果，包括滚动与系统安全区域。

REFINE / 04

视觉审计

定位布局、排版、裁剪和资产差异，修正后再次测量。

05 / Give your agent a contract

一段清楚的提示，
启动正确流程。

连接 MCP 后，把具体节点链接和下面的流程契约交给 AI。它会先发现能力，再询问真正缺失的产品选择。

agent / prompt
使用 fighorse 检查这个 Figma frame。
先调用 discover_fighorse，然后调用 list_experiences，
再调用 get_design_package。
如果缺少平台或资产格式，请问我。
导出资产时带 manifest，不要猜测。
Next / architecture

看见管道内部。

了解为什么 CLI、转换层、上下文层和 MCP 适配器要保持清晰分离。
