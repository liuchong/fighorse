Capabilities / what it actually does

设计事实，
全程在线。

从一个 Figma 链接开始，得到范围明确、带诊断、可导出、可验证的上下文。fighorse 的能力不是孤立命令，而是一条连贯的数据链。

01 / Capability map

八个模块。
同一个事实源。

高级产品工具负责把原始数据变成可行动的上下文；底层接口保留 Figma 公共 REST 语义，供精确查询和调试。

01

设计包

结构、令牌、截图、范围、资产计划和风险诊断的统一入口。

02

资源目录

查看可访问的团队、项目、文件、分支和团队设计库。

03

结构精简

按深度和上下文预算提炼节点树，降低原始 JSON 噪声。

04

设计系统

提取颜色、排版、间距、效果、组件、样式和变量。

05

资产管道

导出截图、组件和图片填充，并生成机器可读 manifest。

06

视觉反馈

比较实现截图和设计参考，形成结构化修正清单。

07

Code Connect

现代模板的生成、解析、验证、预览、发布和删除。

08

Canvas Bridge

通过本地开发插件，在显式授权后创建或修改原生节点。

02 / Design package

一份包，
回答实现前的问题。

design package 是首选高级接口。它不仅告诉 AI 看到了什么，也明确当前范围是否可实现、缺少什么、下一步应导出什么。

输出区域回答的问题下游用途
target + scope当前节点是谁？是否过于宽泛？避免把整个页面或用户流程误当作单个屏幕。
context + tokens结构、尺寸、颜色、字体和约束是什么？提供布局和样式实现事实。
screenshots设计的真实视觉参考是什么？支持实现后的截图对比。
asset_export_plan哪些节点需要导出？用什么格式？生成准确 CLI 命令和 MCP 调用。
diagnostics令牌、字体、截图或范围哪里还不完整？在写代码前暴露风险。
learned_experience过去类似任务踩过什么坑？复用本地、透明、可审查的经验。
design / package
$ fighorse design package \
  "https://www.figma.com/design/<fileKey>/<name>?node-id=<node-id>" \
  --platform web-react \
  --asset-format svg \
  --output ./.fighorse/exports/package.json
03 / Resource catalog

先看地图，
再选目标。

当入口是团队或项目链接时，资源目录先做只读盘点。它不缓存、不批量下载，也不会绕过 Figma 的权限范围。

READY

完整可用

项目、文件和设计库探测成功，可以继续选择具体设计文件或节点。

PARTIAL

保留结果

部分权限不足时保留已经成功的数据，并指出缺少的具体访问范围。

BLOCKED

明确受阻

无法枚举的浏览器根链接不会被误判为团队 ID，而是给出可执行的修正路径。

04 / Assets + tokens

资产可定位，
设计可复现。

图片、组件渲染和图片填充可以导出到受控目录。manifest 记录真实文件结果，让脚本和 AI 不必推断名称。

EXPORT

带清单的资产

支持 png、svg、pdf、jpg 等目标格式；目录限定在项目导出区、项目资产区或用户级 fighorse 导出区。

image exportcomponent exportasset download
AUDIT

结构化视觉审计

把 Figma URL 与应用截图组合，检查尺寸、排版、滚动、裁剪、系统 UI 和字体风险，并产出经验建议。

visual auditproject playbookexperience
05 / Explicit write paths

能写，但绝不
偷偷写。

写能力被拆成互不替代的授权域。启用其中一个，不会顺带打开另一个。

CODE CONNECT

模板连接

生成模板时由 AI 明确提供代码组件上下文；fighorse 本地解析但不执行项目代码。预览和发布需要单独允许模板外发，发布还需要 Figma 写模式。

CANVAS BRIDGE

原生画布修改

Rust 桥接服务连接已配对的本地 Figma 开发插件。画布写入、MCP 写入和脚本执行分别要求明确开关，多会话必须指定目标。

边界同样是一种能力。

fighorse 不声称替代 Figma 官方 Remote MCP 的 Code to Canvas、自动 Code Connect 映射、Make 资源等托管能力。公共 REST 不存在的能力会被明确分流，而不是静默近似。
